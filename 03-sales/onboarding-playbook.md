# Onboarding Playbook — Meridian Research & Advisory

**Purpose:** Convert a signed contract into a live, successful engagement in ≤ 5 business days. Onboarding sets renewal probability — a rushed onboarding is the most common cause of an at-risk account at month 3.

**Goal:** first deliverable on or before the date promised in the SOW, kickoff call booked within 48h of signature, all admin done in the first 3 days.

---

## 1. Post-Sign Checklist (Day 0–1)

Trigger: CRM deal moves to `Won`. Owner runs this within 24 hours.

| Task | Owner | By |
| --- | --- | --- |
| Move deal to `Won`, log final terms, attach flag, source | AE | Day 0 |
| Welcome email to client (template in `/templates`) | AE | Day 0 |
| Contract signed copies filed in CRM + shared drive | AE | Day 0 |
| Invoice 1 issued (per SOW payment terms) | Finance | Day 1 |
| Kickoff call booked (or async brief sent) | AE/CS | Day 1 |
| Workspace + access provisioned | CS | Day 1–2 |
| Client Success lead (Halo) assigned | CS lead | Day 2 |
| First-deliverable calendar set | Delivery lead | Day 2 |

**Welcome email — 3 short paragraphs max:** (1) thank you + what happens next, (2) the kickoff details + who's involved, (3) the one thing we need from them this week (data, access, stakeholders). Physical address + opt-out footer (CAN-SPAM).

---

## 2. Kickoff Call (Day 1–3) or Async Brief

**Preferred: 60-min live call** with client decision maker + deliverer + CS.

Agenda (minute-by-minute):

| Min | Item |
| --- | --- |
| 0–10 | Introductions, roles, Meridian's evidence-first approach (1 line on Meridian OS agents + human owner) |
| 10–20 | Restate the problem from the SOW in their words — confirm we heard them |
| 20–35 | Deliverable walkthrough: what they get, when, format, dependencies |
| 35–45 | Access & data: who provides what, by when (log it) |
| 45–55 | Success measures: what "good" looks like to them at delivery |
| 55–60 | Next steps, owner assignments, follow-up booking |

**Async brief (when live call impossible):** send the brief + 3 questions; require a written reply before work starts. Use it for low-touch accounts only.

**Kickoff outputs (all logged to CRM):**
- [ ] Confirmed stakeholder list + roles
- [ ] Data/access owners + deadlines
- [ ] Success measures in their words
- [ ] Next calendar date (check-in or first-draft review)

---

## 3. Workspace Setup

Provision a client workspace (per-client folder in shared drive + project space in Meridian OS):

- [ ] Client folder created with naming standard: `{Client}-{EngagementCode}/`
- [ ] Subfolders: `/briefs`, `/deliverables`, `/meetings`, `/reports`
- [ ] Access granted to client stakeholders (view-only on drafts until QA-approved)
- [ ] Shared deliverable template set (report, deck, dataset)
- [ ] Calendar sync for check-ins
- [ ] Meridian OS agent scope configured to the client's market/data

**Security:** credentials never shared in email; use the workspace access system; revoke on offboarding. No client data in personal accounts.

---

## 4. Admin Tasks (Day 1–3)

- [ ] Contract filed (signed PDF, countersigned where needed)
- [ ] Invoice 1 issued + payment terms confirmed (net terms per SOW)
- [ ] Client master data in CRM (billing, contacts, source, attach flag)
- [ ] Credentials provisioned for the engagement tools/data sources
- [ ] Any legal/compliance items from SOW Terms closed (NDA, data handling)
- [ ] Renewal date + 90-day renewal task created in CRM
- [ ] Referral context noted (who referred them — see referral playbook)

**Escalation:** if any admin item blocks delivery, escalate to delivery lead same day. Admin gaps do not delay the first deliverable.

---

## 5. First-Deliverable Expectation

Set and keep the SOW's first-deliverable date. This is the trust moment.

- **Quality bar:** passes the QA gate (same gate as proposals — accuracy, no hype claims, evidence cited). A late or weak first deliverable is the #1 renewal risk.
- **Preview:** show a draft/work-in-progress at the mid-point check-in, even if small. Visibility beats surprise.
- **Delivery:** on date, via workspace + a 3-line cover note (what it is, what they should read first, one question back to them).
- **If you're going to miss the date:** tell them BEFORE the date, with a new date and the reason. Never silently slip.

**First-deliverable review call:** book within 7 days of delivery. Walk through it, capture feedback, and set the pattern for the relationship.

---

## 6. Client Success Introduction (Halo)

Introduce the Client Success lead (Halo) as the ongoing relationship owner — the "quarterly temperature check" person — separate from delivery.

Message to client (first 7 days):

```
Meet [Halo], your Client Success lead at Meridian. Halo owns the
relationship side — making sure the work keeps matching where you're
headed. Delivery stays with [Deliverer]; Halo is here for check-ins,
scope changes, and making sure you get maximum value.

```

**Halo duties:** monthly check-in cadence, usage pulse, renewal prep (starting at day 1, intensifying at 90 days), upsell signals routing (see upsell playbook), and being the escalation path if delivery slips.

**Rule:** no client is left to a single person. Every account has AE + deliverer + Halo. One point of contact gone = zero business interruption.

---

## 7. Feedback Loop Start

Begin the feedback loop in week 1 so "good" is defined by the client, not us:

- **At kickoff:** capture success measures verbatim (Section 2).
- **At first deliverable:** structured feedback session — what's working, what's missing, what they'd change.
- **Ongoing:** a standing feedback question at every check-in ("what's the most useful thing we did since last time?").
- **Log it:** all feedback into CRM account notes; tagged for upsell signals and renewal recap material.

**Feedback escalation:** negative or lukewarm feedback → Halo flags the account `At risk`, triggers the save plays in the renewal playbook within 48h. Do not wait for renewal season.

---

## 8. Hand-off to Delivery & Ongoing Cadence

| Week | Cadence item |
| --- | --- |
| 0–1 | Onboarding complete; kickoff + workspace + admin done |
| 1 | First deliverable in progress; mid-point check-in booked |
| 2–4 | First deliverable delivered + review call |
| 4+ | Monthly Halo check-ins; quarterly value review; renewal prep starts at day 90 (see renewal playbook) |

**Definition of done for onboarding:** kickoff held, workspace live, admin complete, first deliverable scheduled, Halo assigned, feedback loop active, CRM complete. Anything less = onboarding not closed → escalate.
