# Daily Retro & Improvement Log — Meridian Research & Advisory

> Version 1.0 · Run nightly by WF-OP-01 · Owned by COO.

## Process

1. Gather inputs: workflow failures, QA returns, KPI deltas, client feedback, escalations, anomalies.
2. Run the 7 questions (`improvement-engine.md`).
3. Log the top 1–3 improvements to the improvement log below.
4. Route actions to owners (Cog/Forge/Mnemos/dept leads).
5. Update the daily KPI snapshot.

## Improvement log (append)

| Date | Source event | Root cause | Action | Owner | Status | Measured impact |
|---|---|---|---|---|---|---|
| _(example)_ | QA return on report | Template missing methodology section | Added to report template + checklist | Mnemos | done | QA pass +4% |

## Daily report template

```markdown
## <YYYY-MM-DD> Retro
**Green:** <what went well>
**Red:** <what failed>
**Root causes:** <why>
**Improvements logged:** <refs>
**Automation queue:** <candidate workflows>
**Escalations:** <none / to owner for X>
```

## Rules

- No day ends without a retro.
- Every logged item has an owner and a follow-up date.
- Items not acted on within 7 days auto-flag to COO.
- Blameless; focus on systems.
